## What this is

A WordPress plugin (WolfThemes "Portfolio") registering a `work` post type and `work_type` taxonomy, with templates, a `[wolf_last_works]` shortcode, and a `wolf-portfolio/last-works` Gutenberg block. Distributed to premium theme customers; updates ship via a self-hosted GitHub updater, so public API surface must stay backward compatible.

## Commands

All build tooling lives in `dev/` (Grunt):

```bash
cd dev
npm install
npx grunt            # default: sass, cssmin, jshint, uglify
npx grunt dev        # same + watch
npx grunt build      # full build (version bump from ../app.config.json, pot file, etc.)
npx grunt phpcs      # PHP CodeSniffer (config: phpcs.xml.dist)
```

There is no test suite. Verify with `php -l` and by loading the plugin on the Local site (`wolfthemes`); Local's MySQL is not reachable from WSL, so runtime checks need the site running.

## Architecture

- `wolf-portfolio.php` — bootstrap only: defines `WFOLIO_PLUGIN_FILE`, registers an `spl_autoload_register` that (a) maps `WolfPortfolio\*` classes to `Functions/`, and (b) lazily `class_alias`es legacy class names (`Wolf_Portfolio`, `Wolf_Portfolio_Shortcode`, …) for themes that reference them. Ends by calling `WFOLIO()` (singleton accessor).
- `Functions/` — namespaced OOP code (`WolfPortfolio\Plugin`, `Admin\Admin`, `Admin\Options`, `Admin\Metabox`, `Admin\Update`, `Frontend\Shortcodes`). `Plugin` wires all hooks, loads everything on `init`, and handles template routing via `template_include`.
- `inc/` — procedural code, deliberately kept: global `wfolio_*` / `wolf_portfolio_*` functions that **themes call directly** (`wolf_portfolio_get_option`, `wolf_portfolio_get_page_id`, `wolf_portfolio_get_template_part`, …), post type/taxonomy registration, template hooks, and the third-party `WP_GitHub_Updater` (`inc/admin/updater.php` — don't refactor it).
- `templates/` — theme-overridable templates (themes override by copying into `<theme>/wolf-portfolio/`). File names and markup are public API.
- `blocks/last-works/` — dynamic block; plain JS, no build step. Renders through the shortcode (`Plugin::render_last_works_block`), so shortcode and block output can never diverge.
- `pack/` — build artifact (previous release layout). Never edit; regenerated by `grunt build`.
- Version lives in `app.config.json` + plugin header + `Plugin::$version`; the Grunt build syncs them.

## Backward compatibility rules

Themes in the wild call the global `inc/` functions, reference legacy class names, and override `templates/`. Never remove or rename: global functions, hook names (`wolf_portfolio_*`, `before_wolf_portfolio_init`), option names (`_wolf_portfolio_*`), the `work` post type / `work_type` taxonomy, template file names, or legacy class aliases. New OOP code goes in `Functions/`; legacy names keep working via the alias map in `wolf-portfolio.php`.
